# autodj.compose: почему звучит просто и куда двигаться (P140–P142, 2026-11-18)

Стас: «то, как сейчас звучит, сильно просто, примитивно; вроде стало лучше, но не намного … он чаще просто семплами слой повторов
одного звучка в течение песни … нужно постоянное звучание инструмента, которое иногда меняет тон … прошу воссоздать другие треки —
не всегда получается, может не хватает инструментов». Плюс пакет Claw для внешнего ревью (11 вопросов, метрики последних треков).

## Что показала проверка кода

1. **Тональный слой — это один записанный звук, перезапускаемый на каждой ноте.** `sfz.voice()` играет запись до её конца:
   пэд-шот на 3 с не держит аккорд на 2–4 такта, поэтому партитура бьёт его снова — отсюда «слой повторов». Петель (loop) в
   плеере нет, легато нет, тембр не меняется внутри ноты и по ходу трека (кроме уровня секции). Синтез в треках не используется
   (CONTEXT Claw), значит «жить» должна сама запись.
2. **Щелчок в верхах во всех треках — настоящий дефект, а не шум метрики.** Тактовый сайдчейн (`mixbus.sidechain_duck`, любой
   `trk.add(..., duck=-6)` без `key=`) ронял громкость за ОДИН сэмпл на каждой доле. Бас без единой гармоники выше 6 кГц
   (−142 дБ) после такого дака давал ступеньку −16 дБFS в полосе 6+ кГц. В `builder.py` так дакаются бас (−6), хук (−3), рамбл;
   в `reftrack.py` — бас, пэд, линии. Поэтому щелчок «не уходил ни от каких правок» и не исчез без хэтов (стал даже громче — вероятно, мастер поднял общий уровень).
   Тот же дефект — в `club_rework.py` / `club_underlay.py` (диджейские ревёрки: оригинал дакается на каждой четверти).
   Ещё источники: `fx.silence_beat` возвращал звук скачком на сильной доле, `fx.stutter` начинал каждый повтор с середины волны.
3. **Воссоздание референса опиралось только на барабаны и бас стемов** (`learn.py` → `reftrack.py`). Плана трека — темпа и сетки,
   тональности, аккордов по тактам, разделов, кривой энергии, частотного баланса, темпа изменений — в числах не было.
4. Метрика `hf_step_dbfs` смешивает щелчок (волна рвётся) и атаку (хэт, снейр, щёлк бочки): она не говорит, где и какой слой.

## P140 — щелчок: исправлено и найдено, где остальное

- `sidechain_duck` (compose, `club_rework`, `club_underlay`): спад громкости за 0,5 мс (приподнятый косинус, заканчивается ровно
  на доле). Глубина, момент и восстановление те же; ступенька −16 дБFS → −51 дБ. `attack_ms=0` — старое поведение.
- `Track.place()`: запись, которая начинается или кончается посреди волны (нарезана по транзиенту), получает 0,5 мс / 3 мс
  только на этом крае (`clicks.declick`); чистые записи не трогаются. `trk.declick = False` — выключить. То же — в концах нот
  SFZ / VSCO, когда запись короче ноты. `fx.silence_beat` и `fx.stutter` больше не прыгают.
- `autodj/compose/clicks.py`: детектор разрывов волны отличает щелчок (ступенька выше окружающего верха на 18+ дБ) от атаки
  (хэт сидит в собственном шуме, 10–16 дБ). Каждый слой проверяется при `trk.add`, шина — в `finish`, каждый разрыв шины
  приписан слою. В сводке: `clicks`, `click_notes` («разрывы волны в слоях: bass 412 шт., худший … на 1:02.4»), `hf_step_t`.
- Гейт «резкий щелчок»: если разрывов нет ни в одном слое и самый резкий перепад — атака, гейт снимается с объяснением
  (у громкого верха свой гейт `high_db`). `META["gates"]["click_strict"] = True` — старый гейт.
- `python -m autodj.compose.clicks scan /путь/к/паку` — список семплов с резкими краями (худшие первыми).

## P141 — записи играются как инструменты (`autodj/compose/evolve.py`)

| Инструмент | Что делает |
|---|---|
| `hold(x, n)` | держит запись сколько нужно: атака как записана, дальше тело продолжается WSOLA (каждое зерно ставится туда, где его волна совпадает с предыдущей: один чистый тон без фленжера), точка чтения медленно ходит по телу записи — звук живёт, а не замирает петлёй |
| `Voice(src)` | одна непрерывная партия из записи: легато без новой атаки, глайд, выдох после фразы, «дыхание» длинных нот, громче = ярче, вибрато с задержкой (по желанию), строка далеко от высоты записи переносится октавой целиком |
| `Ensemble(src, n=4)` | n голосов по аккордам `chords.Plan`: общие ноты держатся, остальные шагают к ближайшему тону следующего аккорда, у каждого голоса своё дыхание, место в панораме и пара центов расстройки (как у живых музыкантов). Источник: одна нота-запись, список записей по регистрам или мультисэмпл (каждый голос просит свою ноту) |
| `grains(trk, src)` | длинные зёрна записи на тонах текущего аккорда: «воздух», который следует гармонии |
| `lane` / `drift` / `sometimes` | автоматизация: по секциям (плавно, без углов; движение заканчивается на границе), медленный дрейф (нет двух одинаковых тактов) и «иногда» — отмеченные моменты в концах фраз и перед новыми секциями |
| `tone(x, bright=, drive=, width=, gain=)` | любой слой через меняющуюся цепочку: фильтр открывается и закрывается, сатурация приходит и уходит, ширина дышит; без щелчков |

Как в партитуре (вместо пэд-шота на каждый аккорд):

```python
from autodj.compose import evolve as V, chords as C, lines as Ln
plan = C.Plan.build("A", trk.tl, "minor_plagal", "lament", seed=seed, rhythm=2).attach(trk)
src = "/path/pad_note_A3.wav"                       # ОДНА выдержанная нота (струнные, пэд, орган, сакс), не аккорд-шот
pad = V.Ensemble(src, n=4, seed=seed).render(trk, layer="pad")          # или V.Ensemble(SFZ("wurlitzer"))
bright = V.lane(trk, {"intro": .3, "drop*": .7, "break": .45}) + V.drift(trk, .06) + .2 * V.sometimes(trk, every=8)
trk.add("pad", V.tone(pad, bright=bright), duck=-4, key="kick", send={"room": .2})
_, top = Ln.topline(plan, rng, 64, 76)                                 # медленная верхняя линия по аккордам
line = V.Voice(src, glide_s=.12, vibrato=(5, 8, .4), bright=.6).render([(s * trk.S16, m, 84, n * trk.S16) for s, n, m, _ in top], trk.N / trk.sr)
trk.add("top", line, role="strings", send={"room": .22})
trk.add("air", V.grains(trk, src, plan=plan, layer="air"), role="texture", send={"room": .4})
```

Аккорд-шоты W.A. («Gm Pad Shot») для `Ensemble` не годятся: это уже аккорд. Их можно держать `hold()` на их собственной высоте
(без транспонирования), а для партий брать ноты-записи или мультисэмплы. `V.body(x)["short"]` скажет, что держать нечего
(плаки, барабаны).

Демо: `docs/examples/evolve_demo.py` — один трек дважды: A (как сейчас: запись на каждый тон аккорда, обрезана по концу записи) и
B (то же, сыгранное). В A брейк проваливается на 10 дБ (записи кончаются раньше аккордов), у пэда 8 «замёрзших» тактов; в B
провалов нет, замёрзших тактов 0, гармония держится непрерывно. Без настоящих записей демо делает заглушку; на VPS:
`AUTODJ_EVOLVE_PAD=/path/note.wav AUTODJ_EVOLVE_PAD_MIDI=57` или `AUTODJ_EVOLVE_SFZ=wurlitzer`.

## P142 — воссоздание референса: план трека в числах (`autodj/compose/blueprint.py`)

- `read(ref)` — темп и сетка тактов (прямая сетка по всем ударам; если трекер зацепился за офф-биты, бочка возвращает его на долю),
  тональность, аккорд на каждый такт (по шаблонам, с учётом гаммы и баса; девятые читаются как их верхнее трезвучие/септаккорд),
  разделы с буквами (одинаковый материал = одна буква) и уровнем, по тактам: громкость, яркость, удары, 6 полос, ширина, бас;
  форма: раз в сколько тактов что-то меняется, самый длинный повтор, доля нового материала, ход громкости.
  Сохраняется рядом: `ref.wav.blueprint.json`.
- `compare(ours, ref)` — похожесть 0..1 и заметки: «в 150–400 Гц у нас на 4 дБ больше», «эталон что-то меняет каждые 2,5 такта,
  у нас каждые 8», «у нас 13 тактов подряд одно и то же», «громкость у эталона ходит на 12 дБ, у нас на 7».
- `match_eq(ours, ref)` — тональный баланс по октавам (без уровня), сглажен и ограничен ±4 дБ → фильтры для премастера.
  Идея matchering, но своим кодом (matchering — GPLv3, последний релиз 2022).
- В партитуре: `META = {"reference": "/path/ref.mp3", "match_eq": .5}` → в сводке `reference` и `reference_notes`, баланс
  мастера подтянут к эталону. Из консоли: `python -m autodj.compose.blueprint ref.mp3 [наш.mp3] [--bpm 124]`.

Порядок воссоздания: `read(ref)` → партитура с теми же темпом, тональностью, разделами (длины, буквы), аккордами по тактам, ходом
громкости → звуки: барабаны/бас по `learn.py`, гармония — `Ensemble`/`Voice` из записей, близких по тембру → рендер с
`META["reference"]` → правки по `reference_notes`, пока похожесть не перестанет расти.

## Ответы на 11 вопросов

1. **Suno/Udio.** Архитектуры не опубликованы. Открытая модель Suno (Bark) — трансформер над токенами аудиокодека EnCodec; сами
   создатели описывают продукт как трансформеры, которые «поют». Нот и теории внутри нет — есть статистика того, как звучат готовые
   записи. Стабильное качество сведения и тембров берётся из данных: модель учится на сведённых и отмастеренных треках и порождает
   весь микс сразу, каждый звук — с учётом всех остальных, поэтому маскировки, баланса и пространства «как в жизни» она не
   собирает, а воспроизводит. Вероятно, сверху ещё и дообучение по предпочтениям слушателей (публично не подтверждено) — масштаб, которого у нас нет.
2. **Наш потолок.** Сейчас — не ноты (после P137 гармония и мелодии меряются как чистые), а звук во времени: один застывший
   звук на партию, перезапуски, отсутствие легато, выдержки и движения тембра, плюс дефекты сведения (щелчок, пиковая нормализация
   `load_sample`, далёкие транспозиции). Мерить разложением: одна и та же партитура с разными звуками (вклад тембра), один и тот
   же звук с разной обработкой (вклад сведения), разные сиды при одинаковых звуках (вклад нот) — и выбор Стаса A/B в каждой паре.
   Демо P141 — пример такой пары: ноты одни, звук сыгран иначе.
3. **«Слышащие» модели.** MERT, MuQ, CLAP — представления (эмбеддинги): хорошо для похожести, жанра, поиска звуков, соответствия
   тексту (CLAP), но не судьи. Audiobox Aesthetics (Meta, 2025: PQ, PC, CE, CU — уже стоит у нас, `ears.abx`, P125) с оценками
   людей за музыкальность согласуется слабо: Spearman ≈ 0,2–0,26 на парных предпочтениях MusicPref, PC — на уровне случайности;
   в работе 2026 года среднее r ≈ 0,2 по пяти наборам, лучшие частные 0,33–0,63. SongEval — 2399 песен, 16 профессионалов,
   5 осей, но это песни с вокалом (англ./кит.), не инструментальная электроника. Вывод: автоматического судьи «музыкально» нет;
   работает свой судья — пары A/B Стаса + эмбеддинги (MERT/MuQ) + наши метрики → маленькая модель предпочтений (Брэдли–Терри).
   Ответ «A» или «B» стоит Стасу секунду — это и решит проблему пустых вердиктов.
4. **Спектрограмма и волна.** Надёжно видно: тональный баланс против эталона (муть 150–400 Гц, резкость 2–6 кГц, нехватка воздуха),
   низ (бочка и бас в 40–120 Гц одновременно, работает ли дак), резонансы (узкие пики над сглаженным спектром — «острый» лид),
   динамику (плоские вершины волны = передавленный лимитер, пик-фактор по секциям), щелчки (вертикальные линии через все полосы),
   стерео (моно-низ, ширина по полосам). Маскировку по миксу не видно — только по стемам (у нас `depth.py` её считает).
   Расстройка видна как биения на увеличенной линейной спектрограмме, но точнее её меряют `tuning.py` и `tonal.py`.
5. **Цикл «рендер → сравнение → правка».** Да, и часть уже сделана: P142 сравнивает с эталоном жанра, подтягивает баланс мастера
   (`match_eq`) и пишет, что править в партитуре. Следующий шаг — то же по слоям: у каждого слоя своя полоса, неглавные слои
   уступают главному в его полосе (см. 8). matchering полезен как идея; брать его код нельзя без GPLv3 для всего проекта.
6. **Мел-спектрограмма в мультимодальную LLM.** Грубое — где дроп, есть ли саб, где пусто — видит. «Хэты тонут», «бас и бочка
   слиплись» — это вопросы относительных уровней во времени, на картинке они ненадёжны. Лучше давать модели числа по стемам
   (они у нас есть) и короткий звук (Gemini слушает аудио сам, `teacher.py`), а финальное слово — Стасу.
7. **Интересное сочетание тембров.** Да, правило есть: в каждый момент один главный (лид, хук или голос), остальные служат —
   тише, темнее, шире или дальше. Контраст по огибающей (тянущийся против ударного), по яркости, регистру и расстоянию; общее
   движение (один дак от бочки, общий фильтр) склеивает; вопрос-ответ передаёт главную роль по времени. Формально: на такт не больше
   одного главного и двух поддерживающих в одной полосе; `depth.py` уже считает планы и маскировку.
8. **Подбор семплов друг к другу (алгоритм).** 1) нормировать по громкости (RMS/LUFS), а не по пику; 2) измерить высоту и центы,
   держать транспозицию в ±5–7 полутонов (ближайшая зона мультисэмпла); 3) обрезать преролл, чтобы атаки стояли на сетке;
   4) у каждого слоя полоса 10–90% энергии; владелец полосы по приоритету (бочка < 100 Гц, бас 60–250, пэд 200–2000, лид 1–5 кГц,
   хэты 6+ кГц); остальным −2…−4 дБ в пике владельца и обрезной фильтр снизу 100–150 Гц; 5) бочка/бас: дак по ключу или раздел
   полос, проверка полярности в 30–120 Гц на ударах бочки (корреляция < 0 → перевернуть или сдвинуть на миллисекунды);
   6) затухание удара короче расстояния до следующего, хвосты — в общую комнату.
9. **Глубина без синтеза.** Безопасно для «живого»: общая комната/пластина (`Space`), параллельная компрессия и лёгкая сатурация,
   октавный дубль записи тихо, длинные зёрна той же записи (P141 `grains`), настоящие шумы (комната, винил, фоли) на −30…−40 дБ,
   микровариации каждого удара (round robin, ±5–10 центов, ±1 дБ, чуть фильтра) — главный приём против «пулемёта». Опасно:
   зёрна короче 50 мс, сдвиг высоты больше ±7 полутонов, быстрые LFO.
10. **Развитие на 4–5 минут.** Мелкое событие каждые 4–8 тактов, крупное — каждые 16–32; не больше 8 одинаковых тактов подряд;
    2–3 подъёма и спада громкости; «убрать, чтобы вернуть» (брейк); смена тембра, регистра, ритма, фильтра, ответ другим слоем.
    Числа уже есть: `arc` (bar_change, same_as_8_bars_ago, longest_unchanged_run_bars), `depth` (замёрзшие слои), P142 `form`
    (change_every_bars, new_material_share, loudness_travel_db). Ворота по желанию: `"arc_run_max": 8`, `"arc_same8_max": .6`.
11. **Что даст больше всего за вложенное время.** 1) убрать дефекты (щелчок — сделано; громкость по RMS вместо пика; пределы
    транспозиции); 2) сыграть имеющиеся записи (P141: выдержка, легато, ансамбль, движение тембра) — это и есть «примитивно» сейчас;
    3) сведение по слоям (полосы, уступки главному) и сравнение с эталоном (P142); 4) несколько хороших тянущихся мультисэмплов
    (струнные, хор/пэд, орган) вместо новых шотов; 5) диапазоны нот под каждый инструмент. Больше шотов — в последнюю очередь.

## Вектор улучшений

| Этап | Что | Готово, когда |
|---|---|---|
| 0, сейчас | P140–P142; перерендерить 2–3 последних трека: пэд → `Ensemble` из той же записи или мультисэмпла, одна сыгранная линия `Voice`, полосы `lane` на пэд/лид; A/B со Стасом | Стас выбирает B в большинстве пар; в сводке нет разрывов волны |
| 1, звук | громкость слоёв по RMS/LUFS; владельцы полос и уступки; полярность бочка/бас; микровариации повторных ударов | нет «резко», «режет», «громкость плохая» в вердиктах; маскировка главного слоя < 30% |
| 2, движение и форма | у каждого тонального слоя 1–2 полосы автоматизации; «иногда»-события; переходы (подъёмы из записей, обратные хвосты, сбивки); ворота формы | longest_unchanged_run ≤ 8, change_every 4–8 тактов |
| 3, воссоздание | из `blueprint` — каркас партитуры (секции, аккорды, темп, тональность, энергия) + подбор звуков по тембру (MFCC/MuQ) + цикл `compare` | похожесть ≥ 0,8 на трёх референсах, Стас узнаёт трек |
| 4, свой судья | пары A/B Стаса → модель предпочтений на эмбеддингах и наших метриках; ранжирование вариантов до отправки | угадывает выбор Стаса ≥ 70% на отложенных парах |
| 5, инструменты | 3–4 семейства тянущихся мультисэмплов, диапазоны по инструменту, жанровые цепочки (хард-техно: параллельный дисторшн, рамбл) | «хард» звучит хардом по сравнению с эталоном |
